# Mixed Original-ReGraph Graph Execution

This nested owner executes the artifact's **11 Little / 3 Big example**, not
the unknown graph-selected best topology in the publication. It does not add
a mixed mode to A4 or the production SST plugin.

| Module | Responsibility |
| --- | --- |
| `preparation.py` | Re-admit original host captures, encode tasks, audit and declare output padding |
| `study.py` | Fixed bounded cases, repetitions and immutable source/binary identities |
| `analysis.py` | Full output, traversal/traffic, lifecycle and sensitivity gates |
| `negative_controls.py` | Original-allocation failure and damaged-input rejection |
| `instrumentation.py` | Independent UBSan full graph build/runs |
| `regression.py` | Pre-edit components and whole A4 equality, verified archived Big captures |
| `delivery.py` | Recheck raw evidence and produce one indexed package |

The thin CLI is `scripts/run_original_regraph_mixed.py`. C++ ownership is in
`cpp/tests/original_regraph/whole_graph/mixed/`: separate input/oracle,
resources, Little/Big wiring, scheduler/state wiring, verification and driver.
The only existing numerical extension is `BigGlobalMerge::begin_partitions`;
the original single-partition entry still delegates with count one.

Read the [implementation contract](../../../../docs/implementation/grasu_regraph/original_regraph_mixed_execution.md)
and [study report](../../../../docs/experiments/comparisons/grasu_regraph_stage_validation/MIXED_GRAPH_EXECUTION.md).
The explicit zero-extended allocation is a compatibility control. Successful
model output does not establish safety of the original host allocation,
realistic HBM timing, or approximately 10% publication-speed matching.
