## Maintenance: cold/hot binary carry

The maintenance parent is `partitioned_run_maintenance` (around line 6862).
The simulator must preserve this order:

1. `partitioned_mark_dirty_frontier` performs the sorted-input preflight and
   directory/frontier update passes.
2. `partitioned_select_binary_target` (line 3726) selects the first globally
   unoccupied cold level. If hot metadata is enabled,
   `partitioned_select_binary_target_for_family_range` independently selects
   the first globally unoccupied hot level.
3. Target zero runs the shared L0 pre-count and writer. Target `t > 0` runs the
   sparse carry writer and merges the new batch with every occupied level in
   `[0,t)`.
4. The target metadata is committed only after all 16 families are staged.
   Lower levels are cleared only after that commit.

An occupied lower level triggers carry immediately; it is not required to be
full. Cold and hot target selection are independent, but the two groups share
the same 16 physical graph HBM ports. Cold family `p` maps to HBM `p`; hot
family `16+s` maps to the same HBM port `s` at the hot layout base.

The carry merge loop (around line 4686) is a sorted multiway merge over the new
batch and old level cursors. Equal `(src,dst)` keys sum signed differential
counts, retain the minimum weight, and emit nothing when the differential sum
is zero. Required simulator-visible work includes:

- full sorted-batch family-filter scans;
- lower-level index and payload reads;
- merge inputs and emitted outputs;
- target bitmap/page-base/row-offset/mask/payload writes;
- metadata commit and lower-level retirement.

The host-precomputed hot bitmap is authoritative. `partitioned_hot_dst_hash`
(line 2837) assigns a hot destination to one of 16 shards. The cycle model must
not infer hotness in the router from current-batch traffic.

## Reader: all families and levels

The split reader builds exact range tasks in
`partitioned_run_convergence_reader` (around line 8580):

1. source values are requested from the compute CU through the reverse AXIS;
2. active records and all 32 x 11 family/level metadata entries are cached;
3. cold families and enabled hot shards are probed for each relevant source;
4. exact edge ranges are binned by 65,536-vertex destination tile;
5. tile begin, edge payloads, and tile end are replayed through the forward
   AXIS stream.

`partitioned_load_range_task_level_cache` reads one occupied word for every
family/level. An occupied entry additionally reads edge count, row count, five
layout offsets, and slice epoch. Source-dependent row lookup and edge payload
reads remain external memory operations and therefore must traverse AXI/HBM.

The initial C++ slice only probes cold L0 and synthesizes its tile list from a
Python-like container. Phase 2 must retain the logical container for payload
correctness while issuing the metadata/index/payload requests generated by all
occupied cold and hot levels.

## Compute: tiny and full tile

`partitioned_run_convergence_compute` starts around line 8958. The first 4,096
ordinary edge words after a non-forced `TILE_BEGIN` are buffered.

- If `TILE_END` arrives within the buffer, the tiny path gathers one persisted
  destination value per buffered edge, relaxes the buffered words, and
  sparse-stores changed destinations.
- If edge 4,097 arrives, the full path loads the complete valid portion of the
  65,536-vertex tile into URAM, replays the 4,096 buffered words, processes the
  overflow word and remaining stream, and emits the active vertices. It always
  counts one full-tile load sweep. A changed tile also performs a full-tile
  store sweep.
- A reader-forced dense tile enters the same full path without speculative
  buffering.

The current C++ compute component fails above the threshold. The replacement
must model the complete vertex-state read sweep, buffer replay, streamed tail,
full store sweep when nonempty, active-output traffic, and finite AXIS
backpressure. It must preserve the 4,095 / 4,096 / 4,097 / 4,098 boundary.

## Multi-round convergence

One split-kernel invocation produces one next frontier; host/device control
launches subsequent rounds until the frontier is empty. A system-level runner
must therefore preserve graph levels across rounds, create a new reader and
compute invocation for each frontier, retain vertex state, and stop only at an
empty next frontier or an explicit iteration cap.

Weighted SSSP correctness is checked after every round and at convergence
against both the mathematical and architecture-width oracles. Per-round
frontier size, processed edges, tile path, FIFO occupancy, AXI/HBM work, and
cycle span remain separately visible.

## Acceptance workloads

| workload | mechanism exposed | required result |
| --- | --- | --- |
| cold L0 real Amazon slice | regression of implemented path | unchanged edge/frontier result and closed request ledger |
| two sequential cold batches | first occupied-level carry | batch 2 targets L1, consumes L0, and leaves only L1 occupied |
| independent cold/hot occupancy | separate target selection | cold and hot targets may differ without losing payloads |
| one hot destination across cold partitions | hot bitmap/shard routing | every marked edge resides in exactly one hashed hot shard |
| 4,095/4,096/4,097/4,098 edges in one tile | tiny/full boundary | first two tiny, last two full, all produce identical SSSP values |
| sparse full tile | full load/store amplification | 65,536-word load and changed-tile store are counted |
| weighted chain with a shortcut | multi-round convergence | converged distances and each intermediate frontier match both oracles |

## Claims boundary

Completion of these mechanisms supports structural and execution-driven timing
claims for the modeled schedule. It does not by itself establish hardware
cycle calibration. HLS loop overlap, compiler burst formation, and measured
clock crossing remain separate validation items and must stay visible in the
limitations until holdout hardware evidence exists.
